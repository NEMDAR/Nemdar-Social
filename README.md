# NEMDAR Social — Design export & implementation foundation

## التشغيل
شغّل `npm start` وافتح http://localhost:8080 لعرض الشاشات الأصلية والتنقل بينها. تشغيل `npm test` يتحقق من قواعد التشغيل الأولية.

## ما تم تسليمه
- ملفات HTML الأصلية المتاحة من Stitch، دون إعادة توليد أو تعديل التصميم.
- فهرس شاشات مع بصمات SHA-256 للتحقق من سلامة الملفات.
- واجهة تنقل للمعاينة، ووضع بعرض 390px لفحص العرض الضيق؛ هذا ليس تصديراً لتصاميم الموبايل المستقلة.
- بداية منطق التشغيل: تعدد الحسابات، منع التكرار، اعتماد قبل الجدولة، تأهيل BANT، واختيار الأهداف الفاشلة فقط لإعادة المحاولة.

## حدود النسخة
هذه حزمة تصميم وبداية تنفيذ، وليست تطبيقاً إنتاجياً. لا توجد مصادقة أو قاعدة بيانات أو نشر أو دفع أو إرسال رسائل فعلي. ملفات Stitch تعتمد على موارد خارجية مثل Tailwind CDN والخطوط والصور، وتحتاج اتصالاً بالإنترنت. الصور وبيانات العملاء وحقوق الوسائط الظاهرة أمثلة تصميمية وليست أصولاً مرخصة مؤكدة.

مصدر الشاشات السبعة الأساسية هو ما أعاده الموصل، وقد لا يمثل آخر مراجعة ظاهرة في واجهة Stitch. لم تتوفر ملفات نسخ الموبايل عبر التصدير. الشاشات الثلاث الإضافية مصدرها استجابة التوليد المحفوظة. لا يُعد تصغير نافذة المعاينة بديلاً عن نسخ الموبايل.

## التنفيذ التالي
1. تحويل التصميم المعتمد إلى مكونات مشتركة وربط الشاشات بحالة التطبيق.
2. إنشاء مخطط clients → brands → accounts، وصلاحيات الفريق وعزل بيانات العملاء.
3. تخزين المحتوى والوسائط والاعتمادات والجدولة وسجل التدقيق.
4. إضافة ربط OAuth لكل منصة حسب صلاحياتها الفعلية؛ إظهار القدرات المتاحة لكل حساب.
5. منفذ نشر بخاصية منع التكرار لكل هدف، وإعادة المحاولة الآمنة والتعامل مع انتهاء التفويض.
6. إضافة الحملات المدفوعة بعد اعتماد الميزانيات، والتحليلات بمصادرها ونطاقاتها الزمنية.

لا تحفظ توكنات المنصات في المتصفح. منطق workflow.js أساس أولي للاختبار ويجب تطبيقه على الخادم قبل التعامل مع حسابات حقيقية.
